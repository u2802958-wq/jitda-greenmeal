# 🍎 교사용 수업 지도안 — 공공데이터로 우리 급식 분석하기

> **주제** 전국 학교급식 공개 데이터(NEIS Open API)로 두 학교의 급식을 비교 분석하는 웹앱 만들기
> **총 차시** 5차시(각 40~50분) · **압축 운영안** 2차시 / 3차시 별도 제시
> **대상** 초등 5~6학년(교사 시연 중심) · 중학교 전학년 · 고등학교 1학년(가장 적합)
> **형태** 1인 1PC 또는 2인 1PC 짝 프로그래밍

---

## 1. 이 수업의 특징

| | 내용 |
|---|---|
| **설치 0** | `index.html` 두 번 클릭이면 끝. 서버·Node·라이브러리 없음 |
| **학생이 만드는 파일은 1개** | `app.js` 하나만 채워 나감 (HTML·CSS는 완성본 제공) |
| **낙오 방지 장치** | `steps/N단계_app.js` 를 덮어쓰면 누구나 다음 단계 합류 가능 |
| **오프라인 대비** | 앱 안 `🎬 예시 데이터로 먼저 보기` 로 네트워크 없이도 진행 |
| **실물 데이터** | 우리 학교 실제 급식이 나오므로 몰입도가 매우 높음 |

### 왜 '급식' 데이터인가
- 학생 **모두가 매일 경험**하는 데이터라 해석에 사전지식이 필요 없다.
- 숫자(영양소)와 글자(요리 이름)가 섞여 있어 **자료 처리의 두 가지 유형**을 한 번에 다룬다.
- "좋은 급식이란 무엇인가"라는 **정답 없는 질문**으로 이어져 데이터 윤리·비판적 사고까지 확장된다.

## 2. 교육과정 연계 (학교 실정에 맞게 성취기준 코드를 기입해 사용하세요)

| 교과/영역 | 연계되는 학습 내용 | 성취기준 코드 |
|---|---|---|
| 정보 – 데이터 | 공공데이터 개방, 데이터 수집·구조(JSON), 데이터 시각화 | |
| 정보 – 알고리즘과 프로그래밍 | 변수, 배열, 반복, 조건, 함수, 비동기 처리 | |
| 정보 – 디지털 문화 | 공공데이터의 가치와 한계, 데이터 해석의 책임 | |
| 실과(초) / 기술·가정 | 소프트웨어와 생활, 식생활과 영양 | |
| 가정 – 식생활 | 영양소, 식품군, 균형 잡힌 식단, 알레르기 표시 | |
| 창의적 체험활동 | 자율탐구, 진로(데이터 분석·영양사·개발자) | |

**교과 융합 제안** — 정보 교사(코딩) + 영양 교사(영양 해석) 공동 수업이 가장 효과적입니다.
영양 교사가 4~5차시의 '해석' 부분을 맡으면 수업의 질이 크게 올라갑니다.

## 3. 수업 전 점검표 (반드시 하루 전에!)

- [ ] 폴더 전체를 학생용 PC에 복사했다 (바탕화면 권장)
- [ ] `index.html`을 두 번 클릭해 화면이 나오는지 **직접 확인**했다
- [ ] 학교 방화벽에서 `open.neis.go.kr` 접속이 되는지 확인했다
      → 브라우저 주소창에 아래를 붙여넣어 자료가 보이면 통과
      `https://open.neis.go.kr/hub/schoolInfo?Type=json&pSize=5&SCHUL_NM=창원고등학교`
- [ ] 막힌다면 → **예시 데이터 모드로 수업**하기로 결정했다
- [ ] NEIS 인증키를 발급받았다 (<https://open.neis.go.kr> → 회원가입 → 인증키 신청)
- [ ] **급식이 있는 날짜**를 미리 찾아 두었다 (방학·주말·시험기간 주의)
- [ ] 비교할 학교 2곳을 미리 정해 두었다 (예: 우리 학교 + 다른 지역 같은 학교급)
- [ ] `app.js`의 `STANDARD` 값이 최신 「학교급식의 영양관리기준」과 맞는지 확인했다
- [ ] 편집기를 정했다 (메모장도 가능 / **VS Code 권장**, 한글 인코딩 UTF-8 확인)

> 💡 **인증키 운영 팁** 학급 전체가 키 없이 쓰면 학교 IP 기준 사용량 제한에 걸릴 수 있습니다.
> 선생님 키 1개를 칠판에 적어 학생들이 각자 앱에 붙여넣게 하는 방식이 가장 간단합니다.

## 4. 차시별 지도안

### 1차시 — 공공데이터 만나기 + 화면 만들기

| 단계 | 시간 | 교사 활동 | 학생 활동 |
|---|---|---|---|
| 도입 | 8분 | "오늘 우리 학교 급식과 서울 어느 학교 급식, 뭐가 더 잘 나왔을까?" 완성된 앱 시연 | 예측·발표, 궁금증 유발 |
| 전개1 | 10분 | NEIS 주소를 브라우저에 직접 입력해 **날것의 JSON** 보여 주기 | 주소를 직접 바꿔 보며 자료 확인 |
| 전개2 | 20분 | `index.html` + `style.css` 배포 → `app.js` 1단계 작성 지도 | 워크북 1단계 따라 코딩 |
| 정리 | 7분 | 날짜가 오늘로 채워졌는지, 시도 목록이 생겼는지 확인 | 결과 확인, 짝과 점검 |

**핵심 개념** 공공데이터 · API · JSON · HTML/CSS/JS 역할 분담 · `querySelector` · 이벤트
**성공 기준** 오늘 날짜가 자동 입력되고, 시도 선택 목록 18개가 생기고, 버튼을 누르면 알림줄이 바뀐다.

> 🎯 **가장 중요한 활동**: 브라우저 주소창에 NEIS 주소를 직접 붙여넣어 JSON을 보게 하는 것.
> "인터넷 주소 하나로 전국 학교 자료를 받을 수 있다"는 경험이 이 수업의 출발점입니다.

### 2차시 — 학교 검색하기 (첫 API 호출)

| 단계 | 시간 | 교사 활동 | 학생 활동 |
|---|---|---|---|
| 도입 | 5분 | 지난 시간 JSON을 다시 띄우고 "이걸 코드로 받아오자" | 복습 |
| 전개1 | 12분 | `fetch` / `async·await` 를 **'주문하고 기다리기'** 비유로 설명 | 개념 이해, 질문 |
| 전개2 | 23분 | 워크북 2단계 코딩 지도, F12 Console 로 `console.log` 확인 안내 | 검색 기능 완성, 학교 2곳 선택 |
| 정리 | 5분 | 키 없으면 5곳만 나오는 이유 설명 → 인증키 등록 | 인증키 붙여넣기 |

**핵심 개념** `fetch` · 비동기 · `URLSearchParams` · 배열 `map` · 동적 이벤트 연결 · `try/catch`
**성공 기준** 학교 이름을 넣고 검색하면 목록이 뜨고, 누르면 학교가 선택된다.

**자주 나오는 질문**
- *"왜 `await`를 붙여요?"* → 인터넷은 느립니다. 답이 오기 전에 다음 줄로 가면 빈 손으로 진행됩니다.
- *"5곳만 나와요"* → 인증키가 없으면 NEIS가 5줄만 줍니다. 제한이지 오류가 아닙니다.

### 3차시 — 급식 불러와 화면에 뿌리기 ⭐ 가장 성취감이 큰 차시

| 단계 | 시간 | 교사 활동 | 학생 활동 |
|---|---|---|---|
| 도입 | 5분 | `DDISH_NM` 원본 글자를 칠판에 크게 띄우기 | "`<br/>`가 뭐예요?" |
| 전개1 | 15분 | **파싱** 개념: 긴 글자를 쪼개 자료로 만들기 (`split`, 정규식 맛보기) | 종이에 손으로 쪼개 보기 |
| 전개2 | 22분 | 워크북 3단계 코딩 지도 | 식단 카드 2장 완성 |
| 정리 | 5분 | 우리 학교 실제 급식이 화면에 나오는 순간 함께 확인 | 캡처·공유 |

**핵심 개념** 파싱 · `split` · 정규식 기초 · 템플릿 문자열 · `Promise.all` · 알레르기 표시 제도
**성공 기준** 두 학교의 실제 식단·열량·알레르기 번호·원산지가 화면에 나온다.

> 📌 **파싱 손으로 해보기 활동(5분, 강력 추천)**
> 칠판에 `통밀밥 (6)<br/>순두부찌개 (1.5.9.13)<br/>사과` 를 적고
> ① `<br/>` 로 자르기 → ② 괄호 안 숫자 떼기 → ③ 표로 정리하기
> 를 학생들이 종이에 직접 해 본 뒤 코드를 봅니다. 이해도가 확연히 달라집니다.

### 4차시 — 그래프 그리기 + 컴퓨터의 한계 발견하기

| 단계 | 시간 | 교사 활동 | 학생 활동 |
|---|---|---|---|
| 도입 | 5분 | "그래프 프로그램 없이 막대그래프를 그릴 수 있을까?" | 예측 |
| 전개1 | 10분 | **막대 길이(%) = 내 값 ÷ 가장 큰 값 × 100** 을 칠판에서 함께 계산 | 계산 연습 |
| 전개2 | 20분 | 워크북 4단계 코딩 지도 (영양소 막대 + 식품군 분류) | 그래프 완성 |
| 전개3 | 10분 | **오분류 찾기 미션**: 컴퓨터가 잘못 분류한 요리 찾기 | 찾아서 사전 수정 |
| 정리 | 5분 | "왜 틀렸을까?" → 규칙 기반 분류의 한계, AI로 이어지는 다리 | 발표 |

**핵심 개념** 정규화(비율 계산) · 데이터 시각화 · 규칙 기반 분류 · 기준값 비교
**성공 기준** 영양소 10개 막대그래프와 기준선이 그려지고, 식품군 누적 막대가 나온다.

> 🔍 **오분류 찾기 미션 (이 수업 최고의 장면)**
> 예시 데이터에서 `리코타과일샐러드` 는 **우유·유제품**으로 분류됩니다(‘리코타’ 때문).
> `단호박크림스프` 는 국물인데 **채소류**로 갑니다.
> 학생이 이를 발견하고 `FOOD_GROUPS` 의 낱말을 직접 고치는 순간,
> "컴퓨터는 뜻을 모르고 글자만 본다"는 것을 스스로 깨닫습니다.
> 초등에서는 코드 수정 대신 **틀린 것 찾아 종이에 적기**까지만 해도 충분합니다.

### 5차시 — 점수 만들기 + 분석하고 토론하기

|---|---|---|---|

| 전개1 | 8분 | 5개 항목 점수 계산식을 함께 읽고 이유 따지기 | 식의 의미 해석 |
| 전개2 | 15분 | 워크북 5단계 코딩(또는 완성본 배포) | 점수·레이더 완성 |
| 전개3 | 12분 | **중요도 슬라이더**로 각자의 기준 만들기 → 순위가 뒤집히는 것 관찰 | 활동지 작성, 근거 발표 |

**성공 기준** 총점·레이더 차트가 나오고, 슬라이더를 바꿨을 때 결과가 어떻게 달라지는지 설명할 수 있다.

> ⚠️ **반드시 짚어야 하는 지도 포인트**
> 1. **실명 학교를 점수로 서열화하지 않는다.** 앱 상단 경고문을 함께 읽습니다.
> 2. 학교마다 예산·인원·지역 식재료 사정·학교급이 다릅니다. 점수는 **질문을 만드는 도구**입니다.
> 3. "내가 가중치를 바꾸면 1등이 바뀐다" → **모든 순위·평가에는 만든 사람의 관점이 들어 있다.**
>    (언론의 학교 순위, 앱스토어 추천, 성적 산출 방식까지 확장 토론 가능)

## 6. 수준별 지도

**빠른 학생을 위한 도전 과제**
1. 시도교육청별 평균 열량 비교하기 (같은 날, 17개 시도의 한 학교씩)
2. 한 학교의 **한 달 열량 변화**를 꺾은선그래프로 그리기 (`MLSV_FROM_YMD` / `MLSV_TO_YMD` 사용)
3. `PROCESSED_WORDS` 를 개선해 오분류를 줄이고, 개선 전후를 비교해 발표하기
4. 우리 반이 정한 새 점수 항목 추가하기 (예: 제철 식재료 점수, 지역 농산물 점수)
5. 알레르기 번호를 골라 두면 해당 요리를 빨갛게 표시하는 기능 만들기

**느린 학생을 위한 지원**
- `steps/N단계_app.js` 를 즉시 덮어쓰게 하여 **다음 단계에 반드시 합류**시킵니다.
- 짝 프로그래밍: 한 명은 타이핑, 한 명은 워크북 읽기 → 5분마다 교대
- 코딩 대신 **낱말 사전(`FOOD_GROUPS`) 채우기**나 **활동지 분석**을 맡겨도 학습 목표는 달성됩니다.

- **영양 교사 인터뷰**: 데이터로는 안 보이는 것 — 예산, 조리 인력, 기호도 조사, 잔반량
  → *"데이터는 세상의 일부만 보여 준다"* 는 결론으로 수업을 마무리하면 매우 좋습니다.
- **타 공공데이터로 확장**: 같은 구조로 학사일정, 시간표, 학교 통계 API도 동일하게 사용 가능
