# 📊 평가 자료 — 루브릭 · 자기평가 · 동료평가

> **평가 철학**
> 이 수업의 평가는 **완성한 코드의 양이 아니라**
> ① 오류를 스스로 찾아 고친 과정, ② 데이터를 근거로 해석한 정도,
> ③ 데이터의 한계를 인식했는지 를 봅니다.
> `steps/` 파일로 코드를 복구한 학생도 **불리하지 않도록** 설계했습니다.

---

## 1. 평가 계획 개요

| 영역 | 비중 | 평가 방법 | 산출물 |
|---|---|---|---|
| 가. 프로그램 구현 | 30% | 관찰, 산출물 점검 | 완성한 `app.js` |
| 나. 문제 해결 과정 | 25% | 관찰, 문답 | 오류 해결 기록 |
| 다. 데이터 해석 | 30% | 활동지 | `03_활동지` |
| 라. 데이터 윤리·태도 | 15% | 활동지, 토론 관찰 | 활동지 Q11~Q13, 발표 |

## 2. 채점 기준표 (루브릭)

### 가. 프로그램 구현 (30%)

| 수준 | 기준 |
|---|---|
| **매우 우수 (A)** | 5단계까지 완성하고, 코드의 각 부분이 무엇을 하는지 **자기 말로 설명**할 수 있다. 도전 과제를 1개 이상 수행했다. |
| **우수 (B)** | 5단계까지 완성했고 주요 함수(`callNeis`, `parseDishes`, `barRow`)의 역할을 설명할 수 있다. |
| **보통 (C)** | 3~4단계까지 완성했다. 또는 완성 코드를 사용했으나 흐름을 설명할 수 있다. |
| **노력 필요 (D)** | 1~2단계까지 진행했다. 교사·동료의 도움으로 실행에 성공했다. |

> 📌 `steps/` 완성 코드를 사용한 것 자체는 **감점 사유가 아닙니다.**
> "이 코드가 무엇을 하나요?" 라는 질문에 답할 수 있으면 **보통(C) 이상**입니다.

### 나. 문제 해결 과정 (25%)

| 수준 | 기준 |
|---|---|
| **매우 우수 (A)** | `F12` 콘솔의 오류 메시지를 읽고 **스스로 원인을 찾아** 해결했다. 다른 학생을 도왔다. |
| **우수 (B)** | 오류가 났을 때 콘솔을 확인하는 습관이 있고, 힌트를 받아 해결했다. |
| **보통 (C)** | 교사의 안내에 따라 오류를 해결했다. |
| **노력 필요 (D)** | 오류가 나면 시도를 멈추었다. |

**관찰 포인트** — 다음 행동이 나타나면 상위 수준입니다.
- [ ] 오류가 나면 먼저 `F12`를 누른다
- [ ] 오류 줄 번호를 찾아 그 근처를 본다
- [ ] "저장했나? 새로고침했나?" 를 스스로 점검한다
- [ ] `console.log`를 넣어 값을 직접 확인해 본다
- [ ] 옆 친구에게 자기 방식으로 설명해 준다

### 다. 데이터 해석 (30%)

| 수준 | 기준 |
|---|---|
| **매우 우수 (A)** | 두 학교의 차이를 **구체적 수치와 특정 요리를 근거로** 설명한다. 예상과 결과가 다른 부분을 찾아 이유를 추론한다. |
| **우수 (B)** | 영양소·식품군 차이를 수치로 정확히 읽고, 어느 쪽이 어떤 면에서 나은지 설명한다. |
| **보통 (C)** | 그래프에서 큰 값과 작은 값을 구분해 읽을 수 있다. |
| **노력 필요 (D)** | 활동지의 수치 기록에 오류가 많다. |

### 라. 데이터 윤리·태도 (15%)

| 수준 | 기준 |
|---|---|
| **매우 우수 (A)** | 가중치를 바꾸면 순위가 바뀐다는 것을 스스로 발견하고, **"모든 평가에는 만든 사람의 관점이 들어 있다"** 는 결론을 자기 말로 말한다. 데이터로 알 수 없는 것을 3개 이상 구체적으로 제시한다. |
| **우수 (B)** | 이 점수가 공식 지표가 아님을 이해하고, 학교 간 우열 판단에 쓰면 안 되는 이유를 설명한다. |
| **보통 (C)** | 교사의 설명 후 점수의 한계를 인식한다. |
| **노력 필요 (D)** | 점수를 학교의 우열로 단정한다. |

## 6. 서술형 평가 문항 (예시)

> 지필평가나 수행평가 서술 문항으로 사용할 수 있습니다.

**문항 1 (3점)** 다음은 NEIS가 준 급식 자료의 일부다.
```
DDISH_NM: "통밀밥 (6)<br/>순두부찌개 (1.5.9.13)<br/>사과 "
```
이 글자를 **요리 이름**과 **알레르기 번호**로 나눈 표를 완성하시오. (3칸)

**문항 2 (3점)** 위 자료를 그대로 화면에 보여 주면 안 되는 이유를 쓰고,
프로그램이 해야 할 일을 한 단어로 답하시오.

**문항 3 (4점)** 칼슘이 A학교 265.8mg, B학교 154.3mg일 때
막대그래프에서 두 학교의 막대 길이(%)를 각각 구하고 계산 과정을 쓰시오.

**문항 4 (4점)** 어떤 급식의 열량이 권장 열량의 130%였다.
이 앱은 이것을 **감점**으로 처리한다. 열량이 **많아도 감점하는 이유**를 쓰시오.

**문항 5 (5점)** A학교 총점 67점, B학교 87점이었다.
그런데 '가공·튀김 절제' 항목의 중요도를 크게 올리자 순위가 바뀌었다.
이 현상이 **우리에게 알려 주는 것**을 서술하고,
뉴스나 인터넷에서 본 다른 순위(예: 학교 순위, 맛집 순위)에 적용해 설명하시오.

**문항 6 (3점)** 이 앱의 급식 점수만으로 학교 급식의 우수성을 판단할 수 없는 이유를
**서로 다른 근거 3가지**를 들어 쓰시오.

**문항 7 (3점)** 컴퓨터가 `배추김치` 를 `과일류`가 아니라 `채소류`로 정확히 분류하도록
이 앱이 사용한 규칙을 쓰고, 그 규칙이 필요한 이유를 설명하시오.
（정답 예: “가장 긴 낱말이 이긴다” — `배`(1글자)보다 `배추`(2글자)가 길어 채소류로 분류된다.）
